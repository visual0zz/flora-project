# 01 总体架构

## 模块划分

flora-sanctum 作为 flora-project 的新模块，内部再分两个 Maven 模块：

```
flora-sanctum/
├── flora-sanctum-core/      -- 纯 Java，无 UI 依赖，专注数据读写
│   ├── crypto/              -- 加密、密钥派生、TOTP（自研：Argon2id + AES-256-GCM-SIV，零第三方加密依赖）
│   ├── model/               -- 数据模型与树（元数据/配置/数据树/节点，见 05）
│   ├── store/               -- 纯字节存储引擎（不负责加密，Codec 由外部注入）
│   └── config/              -- 配置目录（应用级 ~/.flora-sanctum；独立仓库级 config.json）
└── flora-sanctum-app/       -- 单一应用入口：Swing GUI + 同步/HTTP 服务
    ├── bootstrap/           -- 形态判定（lib/ + edit 脚本）、新建/导入仓库
    ├── sync/                -- 本地 git 封装（ProcessBuilder 调系统 git）：commit / push / pull / 冲突处理
    ├── server/              -- 外部密钥服务 HTTP 传输（自 core 迁入）
    └── ui/                  -- Swing GUI（四页：编辑/历史仓库列表/设置/解锁）
```

## 依赖方向

- app → core；core 不依赖任何 UI/CLI/网络/同步。
- app 是唯一可执行入口（单一 jar）：GUI 是唯一交互方式，启动时按仓库形态分流（jar 位于 lib/ 且仓库根含 edit 脚本 → 独立仓库直接解锁 / 应用形态进历史仓库列表页）。
- **core 专注数据读写**：加密（crypto）、块存储（store）、数据模型与树（model）；git/ssh 同步（app/sync）与 HTTP 外部密钥服务（app/server）位于 app。
- core 内部依赖方向（自底向上）：`store` 为最底层的纯字节引擎（不依赖 crypto，编解码由调用方注入 Codec，见 04）；`model`（数据树/节点）插在 `store` 之上（见 05）；`crypto` 由上层（model 等）按需注入，store 不依赖它。
- **store 与数据结构解耦**：store 只提供路径寻址的对象库（key → 字节，编解码由调用方注入 Codec，见 04），不感知上层结构；密码条目等具体结构作为数据树/节点（model/）插在 store 之上（见 05）。更换或新增上层数据结构不需要改动 store。

## 包与导出规则

- 采用项目约定的两层/三层语义层级 + 一级技术层级结构。
- `module-info.java` 只导出 `com.flora.sanctum.{model, model.tree, model.vault, crypto, store, config}` 公开包，内部实现放 `impl` 子包；app 导出 `com.flora.sanctum.app` 及其 bootstrap/ui/sync/server。
- package-info.java 只放顶层包。
- core 中的功能实现使用 flora-root 的 tag 注解标注语义（线程安全、数据敏感性等）。
