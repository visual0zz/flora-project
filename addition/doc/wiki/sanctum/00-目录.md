# flora-sanctum 设计文档目录

## 项目一句话

flora-sanctum 是一个密码管理器：密码库是一个普通文件夹，内含大量散碎的 markdown（一文件一块，`{uuid前2字符}/{剩余字符}.md`，内容为单行 `timestamp:base58`）；加密为自研实现（Argon2id + AES-256-GCM-SIV，零第三方加密依赖）。独立仓库形态自带 `data/ + lib/ + 启动脚本 + standalone.json`（jar 内据此判定孤立模式，不依赖脚本传参）。若该文件夹落在 git 仓库内且基本只有 markdown 对象，则用本地 git 提供自动同步（commit/push/pull，"远端即备份"）；否则管理器只负责自身存储，不主动管理 git。核心性质是"明文的局部修改只引起密文的局部修改"，从而获得小粒度 diff、可合并的并发修改。

## 修改指引

每个文档只覆盖一个方面，架构审查与调整时：

- 改密码学方案（KDF/算法/文件格式）→ 只改 02
- 改安全策略/威胁模型 → 只改 03
- 改存储层（对象库、key、读取模式声明）→ 只改 04
- 改 markdown 块形态（块识别/写回/库形态判定）→ 只改 04b
- 改上层 schema/条目模型/字段组织 → 只改 05
- 改同步策略/远端协议 → 只改 06
- 改界面框架/交互 → 只改 07
- 改依赖 → 只改 08
- 改计划/验收 → 只改 09
- 改导入功能（外部格式解析/映射）→ 只改 10

跨文档的联动修改（如换算法同时影响 02 与 08）需同时更新涉及文档，各文档头部"关联文档"用于提示此类联动。
