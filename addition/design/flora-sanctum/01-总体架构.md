# 01 总体架构

## 模块划分

flora-sanctum 作为 flora-project 的新模块，内部再分两个 Maven 模块：

```
flora-sanctum/
├── flora-sanctum-core/      -- 纯 Java，无 UI 依赖
│   ├── crypto/              -- 加密、密钥派生、TOTP（Bouncy Castle）
│   ├── model/               -- 适配器暴露的公开 API（如条目/字段模型）
│   ├── store/               -- 纯字节存储引擎（不负责加密，Codec 由外部注入）
│   ├── sync/                -- JGit 封装：commit / push / pull / 冲突处理
│   └── server/              -- 外部密钥服务 HTTP 传输
└── flora-sanctum-app/       -- 单一应用入口：无参启动 Swing GUI，有参处理命令行
```

## 依赖方向

- app → core；core 不依赖任何 UI/CLI。
- app 是唯一可执行入口（单一 jar）：无参数启动 GUI，有参数处理 CLI 命令；不拆 cli/ui 两个模块。
- core 内部依赖方向（自底向上）：`store` 为最底层的纯字节引擎（不依赖 crypto，编解码由调用方注入 Codec，见 04）；`model`（适配器）插在 `store` 之上（见 05）；`sync` 用 `store` 的读写；`crypto` 由上层（model 等）按需注入，store 不依赖它。
- **store 与数据结构解耦**：store 只提供路径寻址的对象库（key → 字节，读取模式在引用处声明，见 04），不感知上层结构；密码条目等具体结构作为适配器（model/ 及其实现）插在 store 之上（见 05）。更换或新增上层数据结构不需要改动 store。

## 包与导出规则

- 采用项目约定的两层/三层语义层级 + 一级技术层级结构。
- `module-info.java` 只导出 `com.flora.sanctum.{model,crypto,store,sync,server}` 等公开包，内部实现放 `impl` 子包。
- package-info.java 只放顶层包。
- core 中的功能实现使用 flora-root 的 tag 注解标注语义（线程安全、数据敏感性等）。
