# decision 20260816-1 sanctum UX 交互重设计

## 背景

当前 flora-sanctum Swing GUI 仅"能用"：解锁屏每次都要手输库路径 + 主密码；
锁定后路径丢失，需重新选库；条目编辑只有固定 username/password 两字段、无增删字段、
无搜索、无切换库、条目名不可改。用户反馈交互不自然（期望像 IDEA 工程列表那样，
记住最近打开的库、直接输密码进入）。

## 目标交互模型

以"一个密码管理器桌面应用"的直觉为基准，重做解锁与主界面的交互流：

1. **最近库列表（类 IDEA 工程列表）**：
   - 解锁屏顶部列出最近打开过的库（名称=路径末段，去重、按最近使用排序）。
   - 点击某库即选中并预填路径，焦点落到主密码框，直接输密码回车进入。
   - 底部"打开其他库…"用目录选择器新增一个库（并记录进最近列表）。
   - 上次打开的库自动置顶预选。

2. **锁定即回到解锁屏且记住状态**：锁定/重开时保留最近列表与上次选中库，
   输密码即可再次进入，无需重选路径。

3. **主界面补足缺失能力**：
   - 条目名可编辑（保存时一并提交）。
   - 字段可增/删（+ 添加字段、每行 × 删除该字段），不再固定 username/password。
   - 顶部搜索框：按条目名/字段名/字段值过滤（复用 core 的 searchByType）。
   - 新增"切换库"（回到解锁屏重新选/开另一个库，不退出进程）。
   - 标题栏显示当前库路径。

## 关键取舍

- **最近库记录放用户级配置**（`~/.flora-sanctum/config.json`）：仅存路径字符串，
  非敏感，符合 07-UI设计.md 预留的"最近打开的仓库"位置。
- **不持久化主密码**：安全边界不变，只记住路径，不碰密码学材料。
- **新增 core API**（`deleteField`）：删除字段需按 field→entry→group 解出 DEK 后删除对象，
  与 `deleteEntry` 同构，放 core 更合适（UI 只调公开 API）。
- **范围控制**：本轮聚焦"自然交互 + 高频缺失功能"，不做扁平化大改、不动存储格式。
