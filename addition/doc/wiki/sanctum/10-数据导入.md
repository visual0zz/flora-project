# 10 数据导入（KeePassXC / KDBX4）

## 目标与范围

让用户把外部密码库导入当前 Sanctum 仓库。首版支持 **KDBX 4.x**（KeePassXC 默认导出格式）：

- 主密钥：主密码（必选）+ 密钥文件（可选，哈希型）。
- 解密后映射：分组、条目、标准字段、自定义字段、TOTP。
- 图标不映射（KeePass 数字索引与 Sanctum 命名 SVG 库无权威对应表，留空由用户手动设置）。

**首版明确不支持**：KDBX 3.1（外层 Salsa20 + SHA256 校验，见 §7）、AES-KDF、附件/Binaries、History 历史版本、回收站。

## 导入框架（`io.importer`）

`com.flora.sanctum.app.io.importer` 提供通用导入接口，每种外部格式一个 `Importer` 实现，集中在 `Importers` 注册表：

- `Importer`：`formatName()` / `supports(file)` / `importFile(file, ctx)`；`Importer.forFile(path)` 按文件自动分派，UI 不感知具体格式。
- `ImportContext`：一次导入的上下文——目标 `ObjectTree`、主密码（`char[]`，结束后 `clearSecrets()` 清零）、可选密钥文件、进度回调 `ImportListener`、可选目标分组。
- `ImportResult`：统计写入的分组/条目/字段数与非致命告警。
- `ImportException`：解析/校验失败（密码错误、版本不支持、文件损坏等）。

新增格式只需实现 `Importer` 并在 `Importers.REGISTRY` 追加，无需改动 UI。

## KDBX4 解密流水线（`kdbx.KdbxParser`）

严格对齐 KeePass / KeePassXC 源码语义（KDBX 4.0 / 4.1 规范），全部用官方测试向量验证（见 §5）。

### 头部

- 魔数 `sig1=0x9AA2D903 sig2=0xB54BFB67`，版本 `major==4`。
- 变长字段 `[ID:1B, Len:4B, Data]`，本导入器使用：`2=CipherID`、`3=CompressionFlags`、`4=MasterSeed`、`7=EncryptionIV`、`11=KdfParameters`，`0=End` 结束；`headerData` = 12 字节魔数+版本 + 全部字段（含 End）。
- 4.0 布局：`headerData | SHA256(headerData) 32B | HMAC-SHA256(headerData) 32B`；4.1 布局：`headerData | HMAC-SHA512(headerData ‖ SHA512(headerData)) 64B`（无独立 SHA256 字段）。

### 复合主密钥与 KDF

```
口令分量 rawKey = SHA256(utf8(password))
密钥文件分量 rawKey = SHA256(文件字节)
composite        = SHA256( concat(各分量 rawKey) )      // KDF 输入
transformed      = KDF(composite, KdfParameters)        // Argon2，取原始输出（KDF 后不再哈希）
finalKey         = SHA256(MasterSeed ‖ transformed)
```

- KDF 由 `KdfParameters` 变体字典中的 `$UUID` 决定：`ef636ddf-…`=Argon2d（type 0）、`9e298b19-…`=Argon2id（type 2）；若字典含 `T` 字段则以它为准。参数 `S`(salt)/`M`(bytes，换算 KiB)/`I`(iterations)/`P`(parallelism) 从字典读取，经 `Argon2Kdf.deriveRaw` 执行（Argon2d 为本次新增变体，见 §6）。
- AES-KDF（KDBX3 沿用）暂不支持，报"暂不支持 AES-KDF"。

### 头部 HMAC 认证（KDBX 4.0）

```
K_1      = SHA512(MasterSeed ‖ transformed ‖ 0x01)     // HmacBlockStream 的 K_1
hmacKey  = SHA512(0xFF×8 ‖ K_1)                          // getHmacKey(UINT64_MAX, K_1)
computed = HMAC-SHA256(hmacKey, headerData)
```

与存储值**常量时间比较**，不一致即「主密码错误或文件已损坏」。4.1 用 `HMAC-SHA512(hmacKey, headerData ‖ SHA512(headerData))`。

### 载荷解密

- KDBX4 分块结构：每块 `[HMAC 32B][长度 4B][密文]`，`长度==0` 为终止块；块密钥 `Ki = SHA512(le64(块索引) ‖ K_1)`，消息 `le64(块索引) ‖ le32(块长) ‖ 密文`，4.0 用 HMAC-SHA256、4.1 用 HMAC-SHA512。
- 块密文用 `CipherID` 指定算法解密：`31c1f2e6-…`=AES-256-CBC（PKCS#7）、`d6038a2b-…`=ChaCha20（12B nonce、块计数器 0），均走 JDK `javax.crypto`（不引入 BouncyCastle）。
- `CompressionFlags==GZip` 时用 `GZIPInputStream` 解压。

### 内层头与受保护字段

内层 = `[ID:1B][Len:4B][Data]` 内层头 + XML。内层头给出内层随机流算法与密钥：

- `1=InnerRandomStreamID`（2=Salsa20、3=ChaCha20）、`2=InnerRandomStreamKey`（64 字节种子取 32）。
- XML 中 `Protected="True"` 的字段值先 Base64 解码，再与内层流（**顺序密钥流，跨字段不重置**）逐字节异或还原明文。Salsa20 用 KeePass 固定 8 字节 IV `e8 30 09 4b 97 20 5d 2a`（`Salsa20.java`）；ChaCha20 用 12 字节全零 nonce。

## 数据结构映射（`kdbx.KdbxMapper`）

| KeePassXC 元素 | Sanctum 映射 |
|----------------|--------------|
| `Group`（嵌套） | `GroupNode`（嵌套，`createChildGroup`） |
| `Entry` | `EntryNode`（`createEntry`） |
| `Title` | `EntryNode.name()` |
| `UserName` / `Password` / `URL` | 预设字段 `username` / `password` / `url`（`EntryFields`） |
| 其它 `String/Key=*`（含 `Notes`） | 自定义字段 `createField`（Notes → 键名 `notes`） |
| 字段键含 `totp` 或值以 `otpauth://` 开头 | `FieldNode(kind="totp")` |
| `Times/CreationTime`、`LastModificationTime` | 解析为 epoch 毫秒（解析失败为 null，当前未落库） |
| `UUID` | 不保留，Sanctum 生成新 UUID |
| 图标 / `Binaries` / `History` / 回收站 | 首版跳过 |

顶层无目标分组时自建一个分组（取根组名，缺省 "KeePassXC 导入"）。字段冲突（如重名自定义字段）记入 `ImportResult.warnings` 而非中止。

## 验证（官方向量，非自编码循环）

- 测试 `KdbxOfficialVectorTest` 使用 **KeePassXC 官方测试文件 `tests/data/Format400.kdbx`**（真实 KeePassXC 导出的 KDBX 4.0，Argon2d + ChaCha20），已复制到 `test/resources/…/Format400.kdbx` 且与官方 `cmp` 一致。
- 该文件**主密码是单个字符 `"t"`**（KeePassXC `TestKdbx4.cpp::testFormat400()` 使用 `PasswordKey::create("t")`）——这是调试过程中最易踩的坑。
- 断言：能解析出分组与条目；受保护 `Password` 字段解密为可读明文（`hOkf3tk9sTNG`）；错误密码被拒（头部 HMAC 不匹配）。
- 独立参照：Java Argon2 输出与参考 C 实现（argon2-cffi）在 Format400 参数下逐字节一致，且通过 RustCrypto Argon2 KAT（`Argon2KdfTest`）。头部 HMAC 密钥派生、块 HMAC、内层流偏移等字节级细节均与 KeePassXC 源码（`HmacBlockStream.cpp`、`CompositeKey.cpp`、`Argon2Kdf.cpp`、`TestKdbx4.cpp`）核对。

## 密码学扩展（Argon2d）

flora crypto 的 `Argon2` 原本只实现 Argon2id（type 2）；为 KDBX4 导入新增 **Argon2d（type 0）**：

- `Argon2Kdf.deriveRaw(type, input, salt, memoryKiB, iterations, parallelism, outLen)` 公开入口，按 type 走数据依赖（Argon2d）或数据独立（Argon2id）的索引路径。
- 顺带修正的边界行为（经 KAT 驱动）：`memoryKiB < parallelism` 时的下限处理、`indexAlpha` 有符号取模（`idx < 0` 时回卷 lane 长度）、块预分配为零字节数组。

Argon2 的 `memory` 单位：KeePass `M` 参数以字节存储，换算 KiB（`M/1024`）后调用；`Format400` 的 `M=1048576` → `1024 KiB`。

## UI 入口（`SanctumGui`）

编辑页工具栏「导入」按钮（`doImportKdbx`）：文件选择（`*.kdbx`）→ `Importer.forFile` 分派 → 主密码对话框（`askImportPassword`，含可选密钥文件，密码以 `char[]` 持有）→ 后台线程导入到当前 `ObjectTree` → 状态栏/弹窗展示 `ImportResult`。失败统一提示「主密码错误」或「文件损坏/不支持的版本」。

## 后续扩展

- **KDBX 3.1**：外层 Salsa20 流密码 + 载荷校验 SHA256(明文)，需新增 Salsa20 外层用法（当前 `Salsa20` 仅用于内层随机流）。
- **AES-KDF**：变体字典分支已预留，未实现。
- 附件/二进制、History、回收站、图标完整映射：按需补充。
