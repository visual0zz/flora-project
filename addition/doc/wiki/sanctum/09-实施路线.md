# 09 实施路线

| 阶段 | 内容 | 模块 | 验收 |
|---|---|---|---|
| 1 | Argon2id 派生、SECRET 对象格式（GCM-SIV）、三个顶层 group 的 DEK 树（普通对象/icon/sshKey root，子文件夹链式包裹）、外部密钥服务（字段 kind + 本地 HTTP+JSON） | core·crypto | 单元测试含 KAT 向量；HTTP 加解密/锁定拒绝测试 |
| 2 | 通用对象库：ObjectStore（key 寻址、Codec 注入）、ChangeSet 原子提交；普通文件夹即可用 | core·store | 密文对象读写与原子提交测试（引擎保留裸明文能力） |
| 3 | 密码库适配器：条目记录/组/字段独立对象映射、自描述与扫描构建目录 | core·model | 验证"改一字段只动一个字段对象" |
| 4 | 本地 git 同步封装（可选：init/commit/pull/push、自动冲突按块时间戳仲裁）、SSH 密钥经 GIT_SSH_COMMAND、库形态判定 | core·sync | 双仓库同步与自动冲突测试；普通文件夹无 git 时正常读写 |
| 5 | 形态识别启动分流：独立仓库直接解锁 / 应用形态进选择界面（新建/导入/打开） | app | 作为 core 冒烟测试；GUI 启动（CLI 命令已移除，GUI 为唯一交互） |
| 6 | Swing 主界面（FlatLaf 主题）、解锁屏、托盘、自动锁定、剪贴板清空、Material 主题（明/暗/跟随系统）、用户配置目录（~/.flora-sanctum） | app | 手动验收清单 |
| 7 | CHANGELOG、decision 记录、tag 注解补齐 | 全部 | 对照 AGENTS.md 检查 |

> 模块名对应 01 的分层：`core·crypto` = `flora-sanctum-core/crypto`，`core·store` = `flora-sanctum-core/store`，`core·model` = `flora-sanctum-core/model`，`core·sync` = `flora-sanctum-core/sync`；`app` = `flora-sanctum-app`（唯一可执行入口）。
