# idea20260831-decoy-kdf-amplification

## 背景（问题）

Vault 解开依赖 KDF（当前为 Argon2）把主口令 + 盐派生出主密钥。暴力破解者枚举候选口令，
对每个候选跑一遍 KDF 看是否对齐某个校验值。若真实 KDF 参数（轮数 / 内存 / 并行度）是唯一且
可被识别的，破解者就能只为真实参数付出一次 KDF 成本——它和主人的成本完全相同。

目标不是"防住暴力破解"（那不可能），而是**成本放大（cost amplification）**：让破解者的期望
成本大于主人的解锁成本。主人只跑一组参数（一次 KDF）；破解者不知道哪组是真，面对整个候选
参数池时其期望成本被放大。

本设计讨论一种"诱饵 KDF 参数集"机制。它属于 `flora-sanctum-core` 的存储/加密格式范畴，当前正由
并发 agent 重构该模块；本文**仅作方案记录**，不直接改动 core 代码，落地时需与该 agent 协调。

## 设计

### 1. 核心机制：主口令哈希取模定位参数组

KDF 的三个参数（轮数 `t`、内存 `m`、并行度 `p`）分别存储为三个候选数组，主人的真实参数被隐藏
在候选之中。定位规则：

```
slot_t = H_t(主口令) mod N_t
slot_m = H_m(主口令) mod N_m
slot_p = H_p(主口令) mod N_p
```

- 主人解开时：用三个哈希分别对主口令取模，定位三个数组的某一条，组合得到真实参数组
  `(t, m, p)`，只对该组参数跑一次 KDF。
- 破解者：不知道主口令，无法确定真实参数组对应哪一条，只能面对整个候选参数池。

### 2. 参数池构造

真实参数与假参数按以下方式混合构造：

1. **区间切分**：将"看起来真实的参数范围"按 `10^n` 与 `2^n` 整数节点切分为若干区间。
2. **取值规则**：对每个区间，一半概率取区间右边界，一半概率在区间内部均匀采样，生成候选参数值。
3. **混合排序**：将取到的所有假参数与真实参数放在一起排序。
4. **辅助定位参数**：将排序后的 index 通过带密钥的可逆随机映射函数转变为辅助定位参数。
5. **存储**：Manifest 存储三个辅助定位参数（分别对应 `t`、`m`、`p` 三个数组）。

### 3. 解锁流程

1. 主口令经三个哈希得到三个定位值；
2. 分别从三个辅助定位参数数组中取出对应条目；
3. 经可逆映射反解出真实参数在候选池中的 index；
4. 取回真实参数组 `(t, m, p)` 与对应盐，运行一次 KDF。

### 4. 参数生成的关键约束：诱饵必须统计不可区分

放大的前提，是破解者**无法靠参数本身的统计特征筛掉诱饵**。两种失败模式：

**(a) "围绕真实值 ±抖动"会泄露质心。** 若每组由 `真实值 ± 随机偏移` 生成，N 组参数会自然
以真实值为簇中心聚集，破解者取众数/中位数附近即可识别真实参数。**必须避免这种生成方式。**

**(b) 真实值若成为某维度的 min/max，同样可识别。** 若真实轮数是 N 组里最小的，破解者优先试
最小的即可。

正确生成原则：

1. **从同一个分布 D 采样全部候选**，真实参数只是 D 的一个普通样本，不享受任何特殊位置。
2. **真实参数不应是任一可观测维度（t / m / p）的 min 或 max**；生成后校验并拒绝越界的采样。
3. **包含若干"低成本诱饵"**：保证即使破解者只试便宜的那部分，也至少被这类诱饵兜底放大
   （提供放大的下界）。
4. **包含若干"高成本诱饵"**：若破解者选择"全部试一遍以防漏"，这些高成本组带来最大惩罚
   （提供放大的上界）。
5. **所有候选组都必须是合法的 Argon2 配置**：满足 `m >= 8 * p`（内存不低于并行的 8 倍），否则
   该组本身无效、诱饵暴露为"永远失败的可疑项"，反而成为识别特征。

### 5. 与 honeypot 的区别（范围澄清）

本机制是 **decoy-KDF / 成本放大**，不是 honeypot。Honeypot 需要"诱饵明文"——放一些假条目吸引
攻击者、便于告警。本设计里诱饵只是 KDF 参数配置，**不附带任何诱饵明文**，因此没有告警/蜜罐语义，
纯粹是密码学成本层面的放大。不要在本文基础上自行叠加 honeypot 逻辑，那属于另一主题。

## 验证（落地时应补）

- **定位正确性**：主人用正确主口令能稳定定位到真实参数组，且只运行一次 KDF。
- **放大效果**：破解者在未知真实参数时的期望尝试成本应显著大于主人单次 KDF 成本。
- **统计不可区分性测试**：对生成的候选参数，检验真实参数在 t/m/p 三维上均非 min/max，且各维度
  分布无显著偏离（如 Kolmogorov–Smirnov 不与目标分布相拒）。
- **合法性测试**：所有候选组满足 `m >= 8 * p`，无一组因非法而被实现层拒绝（拒绝本身即识别特征）。
- **主人路径回归**：主人用真实主口令解锁，确认只跑一组 KDF、解锁耗时与单组参数时持平（无回归）。
- **落地点提醒**：本设计涉及 Manifest 结构与 KDF 调用处，归于 `flora-sanctum-core` 加密/存储格式，
  须与正在重构该模块的并发 agent 协调后再实现，避免格式冲突。
