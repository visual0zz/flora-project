# 01 总体架构

## 模块划分

flora-sanctum 作为 flora-project 的新模块，内部再分三个 Maven 模块：

```
flora-sanctum/
├── flora-sanctum-core/      -- 纯 Java，无 UI 依赖
│   ├── crypto/              -- 加密、密钥派生、TOTP（Bouncy Castle）
│   ├── model/               -- 适配器暴露的公开 API（如条目/字段模型）
│   ├── store/               -- 纯字节存储引擎（不负责加密，Codec 由外部注入）
│   └── sync/                -- JGit 封装：commit / push / pull / 冲突处理
├── flora-sanctum-cli/       -- 命令行入口（可选，利于测试与脚本化）
└── flora-sanctum-ui/        -- JavaFX 桌面界面，依赖 core
```

## 依赖方向

- ui → core；cli → core；core 不依赖任何 UI/CLI。
- core 内部：store 为纯字节引擎，不依赖 crypto（编解码由调用方注入 Codec，见 04）；sync 用 store 的读写；model 为最底层。
- **store 与数据结构解耦**：store 只提供路径寻址的对象库（key → PLAIN/SECRET 对象，见 04），不感知上层结构；密码条目等具体结构作为适配器（model/ 及其实现）插在 store 之上（见 05）。更换或新增上层数据结构不需要改动 store。

## 包与导出规则

- 采用项目约定的两层/三层语义层级 + 一级技术层级结构。
- `module-info.java` 只导出 `com.flora.sanctum.{model,crypto,store,sync}` 等公开包，内部实现放 `impl` 子包。
- package-info.java 只放顶层包。
- core 中的功能实现使用 flora-root 的 tag 注解标注语义（线程安全、数据敏感性等）。
