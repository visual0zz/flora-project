# idea20260831-decoy-kdf-amplification

## 背景（问题）

Vault 解开依赖 KDF（当前为 Argon2）把主口令 + 盐派生出主密钥。暴力破解者不在乎"正确性"，
只在乎"成本"：它枚举候选口令，对每个候选跑一遍 KDF 看是否对齐某个校验值。若真实 KDF 参数
（轮数 / 内存 / 并行度）是**唯一且可被识别**的，破解者就能只为真实参数付出一次 KDF 成本，
对其余参数直接跳过——它和主人的成本完全相同（甚至因为主人只跑一次而略低）。

目标不是"防住暴力破解"（那不可能），而是**成本放大（cost amplification）**：让破解者的
期望成本显著大于主人的解锁成本。主人只跑真实的一组参数（一次 KDF）；破解者不知道哪组是真，
若被迫对多组参数各跑一遍，总成本就被放大。

本设计讨论一种"诱饵 KDF 参数集"机制。注意：它属于 `flora-sanctum-core` 的存储/加密格式范畴，
当前正由并发 agent 重构该模块；本文**仅作方案记录**，不直接改动 core 代码，落地时需与该 agent 协调。

## 设计

### 1. 核心机制：哈希取模定位参数槽

Manifest 中不再只存一组 KDF 参数，而是存 **N 组**参数（每组含轮数 t、内存 m、并行度 p，以及相应盐）。
主人的真实参数被隐藏在 N 组之中。定位规则：

```
slot = H(master_key) mod N
```

- 主人解开时：先 `H(master_key)`，取模得到 `slot`，只对该组参数跑一次 KDF 验证。
- 破解者：不知道 `slot`，且 `H` 是单向的，无法反推主人口令对应哪一组。每次口令尝试，它要么
  （a）赌一个 `slot` 只跑一组——有 `1/N` 概率赌对，否则漏掉真实口令；要么
  （b）对全部 N 组各跑一遍以确保不漏——成本放大 N 倍。

这就是放大的来源：**主人付出 1 份 KDF 成本，破解者为保证不漏须付出 N 份。**

### 2. 朴素"快速哈希 oracle"误解的纠正

初看会担心：`H(master_key) mod N` 是个"快速哈希"，破解者能否拿它当 oracle——对任意口令算
`H(pw) mod N` 得到一个槽位，若对齐某个固定值就判定为真？**不能。** 原因：

- `H` 的**输入是主密钥本身**，不是候选口令。主人计算 `slot` 用的是"已经知道的主密钥"，
  破解者并不知道主密钥，它只有候选口令。
- 破解者若想用 `H(candidate) mod N` 当判别，它仍然必须先拥有主密钥才能算 `H`——而这正是它
  要破解的东西。用口令直接算 `H(pw)` 与用主密钥算 `H(mk)` 是两回事，前者得不到主人的槽位分布。
- 因此 `H(master_key) mod N` 不构成"快速判定口令对错"的 oracle；破解者为验证一个候选口令，
  **仍必须跑慢速 KDF**。机制没有引入任何廉价捷径。

### 3. 参数生成的关键约束：诱饵必须统计不可区分

放大的前提，是破解者**无法靠参数本身的统计特征筛掉诱饵**。两种失败模式：

**(a) "围绕真实值 ±抖动"会泄露质心。** 若每组由 `真实值 ± 随机偏移` 生成，那么 N 组参数会自然地
以真实值为簇中心聚集。破解者只需取众数/中位数附近——真实参数几乎必然落在簇心，等于又把它识别
出来了。这会让机制退化为"只跑近似真实值的少量 KDF"，放大失效。**必须避免这种生成方式。**

**(b) 真实值若成为某维度的 min/max，同样可识别。** 若真实轮数是 10 组里最小的，破解者优先试
最小的即可。

正确生成原则：

1. **从同一个分布 D 采样全部 N 组**，真实组只是 D 的一个普通样本，不享受任何特殊位置。
2. **真实组不应是任一可观测维度（t / m / p）的 min 或 max**；生成后校验并拒绝越界的采样。
3. **包含若干"低成本诱饵"**：保证即使破解者聪明地只试便宜的那部分，也至少被这类诱饵兜底放大
   （提供放大的下界）。
4. **包含若干"高成本诱饵"**：若破解者选择"全部试一遍以防漏"，这些高成本组带来最大惩罚
   （提供放大的上界）。
5. **所有组都必须是合法的 Argon2 配置**：满足 `m >= 8 * p`（内存不低于并行的 8 倍），否则该组
   本身无效、诱饵暴露为"永远失败的可疑项"，反而成为识别特征。

### 4. 推荐主机制：等成本 N 槽 + 成本方差叠加

最干净、最不易出错的落地方式分两层：

- **主机制：N 个等成本 KDF 槽**，由 `H(master_key) mod N` 定位。N 组参数成本相同（但数值各异，
  仍满足第 3 节的"真实非 min/max、同分布"约束）。这给出**确定的 N× 放大**，且因为成本一致，
  不存在"高成本诱饵拖慢主人"的风险（主人只跑一组，成本界固定）。
- **叠加层（可选）：在等成本基础上引入成本方差**——部分槽位故意更贵（高成本诱饵）。此时主人
  必须保证自己落在"不贵"的那组（由 `H(master_key) mod N` 的边界规则或额外的"真实标记位"
  确保主人选到便宜组），破解者若全试则被贵组惩罚。

第一层已能独立成立，第二层是增强；若实现第二层，务必保证"主人永远选到低成本组"这一不变量，
否则放大机制以主人自己变慢为代价，本末倒置。

### 5. 与 honeypot 的区别（范围澄清）

本机制是 **decoy-KDF / 成本放大**，不是 honeypot。Honeypot 需要"诱饵明文"——放一些假条目吸引
攻击者、便于告警。本设计里诱饵只是 KDF 参数配置，**不附带任何诱饵明文**，因此没有告警/蜜罐语义，
纯粹是密码学成本层面的放大。不要在本文基础上自行叠加 honeypot 逻辑，那属于另一主题。

## 验证（落地时应补）

- **放大倍率可证**：在 N 组等成本配置下，验证"破解者为保证不漏须跑 N 组"这一论断，对照主人
  单次 KDF，确认期望成本比 = N（或含方差后的期望）。
- **统计不可区分性测试**：对生成的 N 组参数，检验真实组在 t/m/p 三维上均非 min/max，且各维度
  分布无显著偏离（如 Kolmogorov–Smirnov 不与均匀/目标分布相拒）。
- **合法性测试**：所有 N 组满足 `m >= 8 * p`，无一组因非法而被实现层拒绝（拒绝本身即识别特征）。
- **主人路径回归**：主人用真实主密钥解锁，确认只跑一组 KDF、解锁耗时与单组参数时持平（无回归）。
- **落地点提醒**：本设计涉及 Manifest 结构与 KDF 调用处，归于 `flora-sanctum-core` 加密/存储格式，
  须与正在重构该模块的并发 agent 协调后再实现，避免格式冲突。
