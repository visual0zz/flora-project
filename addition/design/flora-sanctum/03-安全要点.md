# 03 安全要点

## 内存

- 密码不用 `String` 承载：用 `byte[]`/`char[]`，用后 wipe（fill(0)）。
- DEK/KEK 只在解锁期间驻留内存，锁定即丢弃。
- **内存秘密清除范围**：锁定/解锁失败时，除 KEK/DEK 外，还需同步清除以下驻留秘密并置空（fill(0)/释放引用）：
  - keyId 预计算索引表（`map<short, map<dek_hash, DEK>>`，见 02）——含每个 DEK 及其哈希，须整表清除；
  - 内存中构建的解密目录（组树/条目/字段值/SSH 私钥/远端配置，见 05）——含全部明文用户数据；
  - 解锁中途派生的 encKey、manifest MAC 验证密钥。
- 统一由锁存器（lock）持有上述全部对象，锁定调用一次性销毁；不散落在 UI/core 各自持有。
- 若解锁失败（主密码错误或仓库损坏，见"解锁失败"），同样必须清空已派生但未完成的中间物，确保失败后可安全重试。

## 解锁失败

- 主密码错误与仓库损坏都表现为 GCM-SIV tag / manifest MAC 校验失败（见 02），**不向 UI 区分具体原因**，统一提示"解锁失败"。
- 解锁失败后：清空本次派生的一切中间物（KEK/DEK/encKey/MAC 密钥/索引），内存回到未解锁态，可安全重试。
- 不提供"密码错误"与"数据损坏"的自动区分——避免向攻击者泄露仓库状态线索；用户需凭重试/备份排查。

## 剪贴板

- 复制密码后定时自动清空（默认 30s，可在 07 UI 设置）。

## 自动锁定

- 不活动默认 5 分钟自动锁定：丢弃 KEK/DEK，再次操作需主密码。

## 落盘与日志

- 不落盘临时明文文件。
- 日志禁止出现明文与主密码。
- SSH 私钥默认存 vault（SECRET 对象，与条目同级保护）：解锁后在内存持有、锁定即弃，不落明文盘；也可用系统 ssh-agent（见 06 Git 同步）。主密码即所有凭据的单点，需强口令 + 归档备份。
- 远程仓库**无用户数据明文**：组记录、条目、字段、密钥、远端配置、图标均为 SECRET 对象且全为随机 UUID 命名，仓库中除 manifest 明文引导块（见 02/04b）外无任何用户数据明文；目录在解锁后内存构建，无持久索引。

## 备份

- 备份即远端：鼓励配置多远端。
- 另提供导出加密归档命令（core 提供，CLI/UI 调用）。

## 威胁模型（简）

- 对抗目标：仓库文件落入他人之手（密文不可读、不可篡改不被发现），含**储存方（git 远端/备份）主动作恶**（篡改、混入伪造文件；不防整体回滚，见 02）。
- 对抗手段：AES-256-GCM-SIV 认证 + Argon2id 抗暴力 + 防降级（见 02）；针对篡改/混入的完整性设计见 02"完整性设计"。
- 不防护：本地已解锁环境下的恶意进程（本机信任模型）。
