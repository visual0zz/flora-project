# 05 密码库适配器

密码管理 schema 是插在通用对象存储（04）之上的适配器，全部约定建立于 key + 对象。换成其他数据结构时只换适配器，底层不动。

## 隐私目标

外部（无主密码）拿到仓库，最多只能看到一堆随机命名的密文文件；**看不到**组名、条目名、字段名、字段数量、字段值，连组的数量与嵌套形状也不可见。

## 逻辑模型

- 文件夹（组）：树形，节点 = 组记录（SECRET 对象，含父组引用）。
- 条目：隶属于某组（记录内含所属组 id），**整条打包**为一个 SECRET 对象（字段名 + 值 + 元数据全部在密文内）。
- 索引：单个 SECRET 对象（加密的组树 + 条目名 + iconId 缓存），解锁后载入内存；锁定状态无列表。

## 映射：逻辑概念 → key 与对象

| 逻辑概念 | 底层表示 |
|---|---|
| 组记录（name/parentGroupId/createdAt） | SECRET 对象；key = `secret/<组UUID>` |
| 条目（整条打包，含 groupId） | SECRET 对象；key = `secret/<条目UUID>` |
| 自定义图标 | PLAIN 对象；key = `plain/<随机UUID>`（条目记录以 iconObjectId 引用，可选） |
| 索引缓存（组树、条目名、iconId） | SECRET 对象；key = `secret/index`（保留名，可重建） |
| SSH 私钥 | SECRET 对象；key = `secret/<密钥UUID>`（远端配置引用，可选多个） |
| 远端配置（名称、URL、key 引用） | SECRET 对象；key = `secret/remote`（权威，不可重建） |

- **secret/ 下平铺**：组与条目同命名空间，每个逻辑对象一个文件，key 即文件名（`secret/<UUID>`）；无目录嵌套。
- 组记录、条目对象、索引：`put(key, data, cipherCodec)`（密文）；图标：`put(key, data, null)`（明文）。存储引擎本身不感知加密，见 04。
- **plain/ 与 secret/ 形式一致**：所有对象（组、条目、图标、索引）统一 UUID 命名；引用关系存于对象内容（如条目记录引用图标对象的 UUID）。
- 文件类型靠内容自描述（解锁后按解密负载区分组记录/条目），无需类型前缀。
- 条目/组 id 在创建时用 SecureRandom 生成 UUID v4（RFC 4122：`xxxxxxxx-xxxx-4xxx-yxxx-xxxxxxxxxxxx`，y ∈ 8/9/a/b；Java `UUID.randomUUID()`），**终身不变、与内容无关**（不哈希名字）：改名只改对象内容，id 保持稳定。

## 条目对象内容（加密 JSON）

```json
{
  "version": 1,
  "name": "微博",
  "groupId": "<组UUID>",      // null = 根组（无文件夹）
  "createdAt": "2026-08-12T10:00:00Z",
  "iconId": 1,                // 内置图标集索引
  "iconObjectId": null,       // 自定义图标（PLAIN 对象 UUID），存在即优先于 iconId
  "fields": {
    "password": "...",
    "username": "...",
    "totp": "...",
    "自定义字段": "..."
  }
}
```

- 字段名与值都在密文内：外部看不到字段名、字段数、各字段大小。
- 组记录：`version`、`name`、`parentGroupId`、`createdAt`。
- 不记录修改时间：任何字段修改都会重写整个条目对象，记录它没有意义。

## 局部性

- 改任一字段 → 只重写该条目对象（一个文件）；其他条目不动，git 只见一个文件变化。
- 条目改名/增删字段 → 同样只重写该条目对象。
- 移动条目/组 → 重写该对象（条目改 groupId / 组改 parentGroupId），低频操作，1 个文件。
- 换主密码 → 只重写 key.bin，全部条目对象不动（见 02）。

## 字段级拆分模式（可选）

默认整条打包。对希望更细 git diff / 并发合并的用户，可对**单条目**开启字段级拆分：该条目展开为目录 `secret/<条目UUID>/`，内含元数据文件与每字段一个 SECRET 对象，key `<条目UUID>/<HMAC(blindKey, 条目id:字段名)前16hex>`（盲化与防字典攻击见 04），字段名清单存于元数据文件（加密）。

- 收益：改一个字段只重写一个文件；同条目不同字段的并发修改可合并。
- 代价：字段数量与形状（哪些字段存在）对外可见。
- 两种模式互不兼容，条目创建时选定。

## 一致性规则

- 事实来源：组记录与条目对象（SECRET）；`index` 是加速缓存，可删可重建（解锁后全量扫描、解密负载区分类型后回填）。
- 索引损坏/缺失：解锁后重建；锁定状态无列表（UI 显示锁定态）。
