# 03 存储设计

## 粒度取舍

| 方案 | 优点 | 缺点 |
|---|---|---|
| 每条目一个加密文件 | 文件少、简单 | 改一个字段重写整个文件，同条目并发修改冲突 |
| 每字段一个加密文件（目录式） | 最贴合"局部修改→局部密文"，Git 合并友好 | 文件多（每条目约 5~10 个） |

**结论：目录式，每条目一个目录、每字段一个文件。**

## 仓库布局

```
vault/                      -- Git 仓库根
├── key.bin                 -- DEK（被 KEK 加密，见 02）
├── manifest                -- 格式版本、KDF 参数
├── index.json              -- 可选明文索引
└── entries/
    └── <entry-uuid>/
        ├── meta            -- 字段名清单、自定义字段（加密）
        ├── password        -- 字段值（加密，格式见 02）
        ├── username
        ├── url
        ├── totp
        └── notes
```

## 条目模型

- 内置字段：name、url、username、password、totp、notes。
- 自定义字段通过 `meta` 描述，值为额外文件或合并进 meta（按字段数权衡）。

## 明文索引

- `index.json` 存条目名 → 目录映射等不敏感信息，列表渲染无需解密。
- 若条目名也敏感：索引整体加密，解锁后重建到内存，不落盘。

## 局部性

- 修改任一字段只重写该字段文件，Git 只见一个文件变化（详见 04）。
- 文件名只用 UUID，不含明文信息，目录结构不泄露内容。
