# 01 总体架构

## 模块划分

flora-sanctum 作为 flora-project 的新模块，内部再分两个 Maven 模块：

```
flora-sanctum/
├── flora-sanctum-core/      -- 纯 Java，无 UI 依赖，专注数据读写
│   ├── crypto/              -- 加密、密钥派生、TOTP（Bouncy Castle）
│   ├── model/               -- 数据模型与树（元数据/配置/数据树/节点，见 05）
│   ├── store/               -- 纯字节存储引擎（不负责加密，Codec 由外部注入）
│   └── config/              -- 用户全局配置（~/.flora-sanctum）
└── flora-sanctum-app/       -- 单一应用入口：Swing GUI + CLI + 同步/HTTP 服务
    ├── sync/                -- 本地 git 封装（ProcessBuilder 调系统 git）：commit / push / pull / 冲突处理
    └── server/              -- 外部密钥服务 HTTP 传输（自 core 迁入）
```

## 依赖方向

- app → core；core 不依赖任何 UI/CLI/网络/同步。
- app 是唯一可执行入口（单一 jar）：无参数启动 GUI，有参数处理 CLI 命令；不拆 cli/ui 两个模块。
- **core 专注数据读写**：加密（crypto）、块存储（store）、数据模型与树（model）；git/ssh 同步（app/sync）与 HTTP 外部密钥服务（app/server）位于 app。
- core 内部依赖方向（自底向上）：`store` 为最底层的纯字节引擎（不依赖 crypto，编解码由调用方注入 Codec，见 04）；`model`（数据树/节点）插在 `store` 之上（见 05）；`crypto` 由上层（model 等）按需注入，store 不依赖它。
- **store 与数据结构解耦**：store 只提供路径寻址的对象库（key → 字节，读取模式在引用处声明，见 04），不感知上层结构；密码条目等具体结构作为数据树/节点（model/）插在 store 之上（见 05）。更换或新增上层数据结构不需要改动 store。

## 包与导出规则

- 采用项目约定的两层/三层语义层级 + 一级技术层级结构。
- `module-info.java` 只导出 `com.flora.sanctum.{model,crypto,store,config}` 公开包，内部实现放 `impl` 子包；app 导出 `com.flora.sanctum.app` 及其 command/sync/server。
- package-info.java 只放顶层包。
- core 中的功能实现使用 flora-root 的 tag 注解标注语义（线程安全、数据敏感性等）。
