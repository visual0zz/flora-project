# 09 实施路线

| 阶段 | 内容 | 模块 | 验收 |
|---|---|---|---|
| 1 | Argon2id 派生、SECRET 对象格式（GCM-SIV）、根对象（type=root）持 KEK 包裹的 root DEK 与子文件夹 DEK 树（链式包裹）、外部密钥服务（字段 kind + 本地 HTTP+JSON） | core·crypto | 单元测试含 KAT 向量；HTTP 加解密/锁定拒绝测试 |
| 2 | 通用对象库：ObjectStore（uuid 寻址、Codec 注入）、两层目录一文件一块；普通文件夹即可用 | core·store | 密文对象读写与布局测试（引擎保留裸明文能力） |
| 3 | 密码库适配器：条目记录/组/预设字段（独立块）/自定义字段（customField）映射、自描述与扫描构建目录 | core·model | 验证"改一字段只动一个字段块" |
| 4 | 本地 git 同步封装（可选：init/commit/pull/push、自动冲突按块时间戳仲裁）、SSH 密钥经 GIT_SSH_COMMAND、库形态判定 | app·sync | 双仓库同步与自动冲突测试；普通文件夹无 git 时正常读写 |
| 5 | 形态识别启动分流：jar 内检测 standalone.json → 独立仓库直接解锁 / 应用形态进历史仓库列表页（新建/导入/打开合并于此） | app | 作为 core 冒烟测试；GUI 启动（GUI 为唯一交互） |
| 6 | Swing 四页（编辑/历史列表/设置/解锁）、FlatLaf 主题、托盘、自动锁定、剪贴板清空、配置目录（应用级 ~/.flora-sanctum / 仓库级 standalone.json） | app | 手动验收清单 |
| 7 | CHANGELOG、decision 记录、tag 注解补齐 | 全部 | 对照 AGENTS.md 检查 |

> 模块名对应 01 的分层：`core·crypto` = `flora-sanctum-core/crypto`，`core·store` = `flora-sanctum-core/store`，`core·model` = `flora-sanctum-core/model`；`app` = `flora-sanctum-app`（唯一可执行入口，含 sync/server/ui/bootstrap）。
